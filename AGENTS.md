# Architecture rules
- Event QR display/export share one configuration and require a decoded same-origin embedded logo before PNG export; this prevents quiet-zone loss and unbranded downloads.
- Email confirmation state is tab-scoped and separate from guest credentials; callbacks revalidate Auth and matching email before legacy profile completion or guest claim, never dispatching managed welcome mail.
- Core audit repairs are reviewed as ordered source-only SQL under `supabase/repair-staged`, not mixed with historical draft migrations; this preserves independent execution and rollback review.
- Event mutation RPCs acquire the event row before request/vote/profile writes; browser vote and playback table mutations are revoked to avoid tuple-lock inversion with request_song.
- Staged RPC contracts live in a typed adapter separate from generated hosted types until reviewed SQL is applied; generated types must always describe the actual hosted schema.
- Admission uses a per-identity advisory mutex then an event row mutex and rolling logs; shared network addresses do not determine guest admission quotas.
- Follow-up SQL lives under `supabase/repair-followup`; canonical payment functions are deployment-gated by an installed contract marker and must not be deployed before independent installation; this prevents code/schema mismatch.
- Tip reservations and settlement use a per-user advisory mutex before tip locks and immutable provider parameters; ambiguous provider calls retain quota until evidence-backed reconciliation.
- Shared React hooks/context and visual variants live outside component files; this preserves fast-refresh boundaries without disabling lint rules.
- Managed app-email sending remains a fail-closed no-network adapter until official sender-domain scaffolding; never create project email queues or fabricate provider APIs.
- Shared Edge payment evidence lives under `supabase/functions/_shared`; sibling function imports are not bundled by deployment.
- Event song counters and user-selected votes are read with one left-embedded relational statement; split HTTP reads can observe different transaction snapshots.
- The MCP Vite plugin owns its generated function output; exclude that exact artifact from lint while keeping all authored MCP inputs linted.
- Stripe key format validation lives in an SDK-free shared helper used by all Stripe constructors and mode inference; this keeps restricted-key compatibility consistent and testable without provider calls.
- The guest-token probe is isolated in schema `repair_guest_probe` behind one service-role RPC and the `guest-token-probe` function; it must never read/write app tables or auth, so it can be dropped without touching the app.
- Real guest backend candidates live under `supabase/guest-integration` with explicit actor kernels and a service-only API; disabled/source-only independent installation preserves deployed Auth behavior and probe isolation.
- Guest principals reference protected public profile keys; only profiles link to Auth, and registered profile retirement precedes restricted Auth deletion to avoid managed deletion triggers and cascade lock inversion.
- Guest claim exclusion is acquired at outer writer entry or BEFORE STATEMENT before tuple locks; legacy late row-trigger exclusion must never be introduced because it can invert event locks.
- Guest live invalidations will use a verified-token receive-only Edge WebSocket relay with worker-shared two-second private revision polling; one poller/event/worker stops with the last socket, avoiding Realtime policies, quotas and idle cron jobs.
- Guest read session validation chooses shared event/session locks at entry while mutations choose exclusive locks; authenticated and guest snapshots share one safe alias-aware SQL projection to avoid DTO and transaction drift.
- Guest stream SQL is a separate 010 overlay with private transactional revisions and service-only token/batch RPCs; native socket adapters stay separate from pure hubs and protocol tests so no-network lifecycle checks cover shared polling.
- Guest application source uses a backend-scoped default-off actor provider and a separate 011 overlay; explicit claim intent and service-validated supporting adapters preserve Auth identity and independent core review.
- Guest joins serialize bootstrap and session access with a backend-scoped Web Lock; unsupported browsers may reuse persisted proof but must refuse fresh creation, preventing cross-tab identity forks.
- Guest provider snapshots are keyed to the selected event/session and coalesce in-flight reads; stale selection/Auth/unmount results never supply another actor's profile.
- Guest API and supporting POST handlers share SDK-free bounded object-JSON parsing before actor resolution; typed malformed/UTF-8 and size errors prevent Auth/provider work.
- Guest per-row read projections compute the canonical actor/alias set once (materialized) and alias lookups are index probes; per-row non-inlinable alias calls held the event SHARE lock long enough to convoy writers into statement timeouts.
